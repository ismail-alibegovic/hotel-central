## Added or corrected during this audit
* New: Offer fields (price/validity/button), room **Price**, **Footer texts** (EN/BS), **Footer links** menu location, Instagram link, templates *Price list* and *Opening hours* (library now 33), nested menu items in the full-screen menu, remembered old slugs (301), sharing-image picker, Bosnian opening-hours labels, "Create copy" keeps sub-page parent.
* Protection: Elementor Site Settings (Kit) and Additional CSS closed to Editors (`HC_EDITORS_MAY_EDIT_DESIGN` lifts it); Editor admin menu reduced to Menus under Appearance; Elementor Pro promotion page hidden.
* Fixed defects found by the tests: template placeholder alt text ("Replace this photograph") leaked into the Media Library and public pages; Elementor editor preview collapsed fact/price tables and galleries (first/last-child rules vs. Elementor's overlay elements); template buttons used `#` links (Elementor console error); pages without a hero now start below the solid header; WordPress block editor hid the SEO/Parent boxes → classic screen for pages.
* Fidelity vs. Next.js re-measured after the CSS changes: ≤ 1.1 % page-height difference at 390/768/1440 (unchanged).

## Not verified / needs staging or Hotel Central
* **External e-mail delivery** (password reset, contact form) — needs SMTP/transactional mail at staging; only the local capture was verified.
* Live eZee booking, real hosting/TLS/DNS, performance on the real host, Firefox/Safari/real phones — not tested here.
* Bosnian guide/training text: native-speaker proofreading and the hotel's own names for roles/people.
* Hotel Central input: confirm that *Fitness Club* and *Day Spa* stay one "Club & Spa" page (as on the current site) or should become two; real offers and prices; who gets Administrator vs Editor accounts.
* Known Elementor Free/Polylang Free limits: see `docs/ELEMENTOR-SYSTEM.md` (no Theme Builder/Custom CSS; new pages/rooms take the language of the admin-bar filter; Elementor logs a harmless `panel/global/open` console error when an Editor tries to open the protected Site Settings).

**Ready for public staging deployment?** Yes for the CMS functionality — 14/15 requirements fully verified, the remaining one (10) depends on staging mail infrastructure rather than on code. Pre-conditions on staging: configure SMTP, set the environment type to `staging`, set `HC_EDITORS_MAY_EDIT_DESIGN` only if wanted, create the real Editor accounts, keep "Discourage search engines" on until launch.
